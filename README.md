# Hayo

待ち合わせ中の「あと何分？」「今どこ？」を、位置共有と写真ミッションで楽しめる体験に変えるiOSアプリです。メンバーは招待コードで一時グループに参加し、地図で互いの位置を見ながら、移動中のフォトミッションや写真リアクションを楽しめます。

**4人チームで開発したプロジェクトのportfolio mirrorです。** 元の開発リポジトリは [NxTEND-THE-HACK/2026-Team-25](https://github.com/NxTEND-THE-HACK/2026-Team-25) です。チームメンバーの了承を得て、このミラーをPublic公開しています。開発では友人のMac 1台を4人で共同利用したため、Gitのcommit authorや履歴は各メンバーの個人貢献を正確・完全には反映していません。

## 30秒でわかるHayo

- **課題:** 待ち合わせ中の連絡や到着確認が単調で、参加者同士の状況もわかりにくい。
- **解決:** 招待コードで集まったメンバーの位置・到着状況を共有し、移動中に届く写真のお題を通して待ち時間をゲーム化。
- **主な機能:** リアルタイム位置共有、出発予定時刻に応じた「はよ」通知、制限時間付きフォトミッション、写真投稿とリアクション、到着ランキング。
- **成果:** THE HACK 東海予選4位入賞。全国の舞台でプロジェクトを発表しました。
- **プライバシー設計:** アカウント登録なしで匿名認証を利用。全員の到着後10分を経過したグループのデータをCloud Functionsで削除します。24時間以上経過した古いグループも定期処理の対象です。
- **開発:** NxTEND THE HACK 2026 / Team 25、4人チーム。

## 技術とアーキテクチャ

| 領域 | 採用技術 | 役割 |
|---|---|---|
| iOSアプリ | Swift 5、SwiftUI | 画面、画面遷移、状態に応じた表示 |
| 地図・位置 | Google Maps SDK for iOS、MapKit、CoreLocation | 地図・メンバー表示、目的地検索、位置取得 |
| カメラ・通知 | AVFoundation、UserNotifications | 写真撮影、アプリ内・ローカル通知 |
| 認証・同期 | Firebase Authentication（匿名）、Cloud Firestore | アカウント登録なしの識別、グループ状態のリアルタイム同期 |
| 写真 | Firebase Cloud Storage | 投稿写真の保存 |
| サーバー処理 | Cloud Functions for Firebase（Node.js 20） | ミッション予約、全員到着の判定、期限後のデータ削除 |

```text
iOS (SwiftUI)
 ├─ CoreLocation / Google Maps SDK / MapKit
 ├─ AVFoundation / UserNotifications
 └─ Firebase Auth ─ Firestore ─ Cloud Storage
                         ↑
              Cloud Functions (Node.js)
              ミッション・到着判定・削除
```

### 技術選定の考え方

以下はリポジトリ内の実装から読み取れる構成の適合性です。選定の背景として明記された記録ではなく、コードに基づく説明です。

- **SwiftUIとiOS標準API:** 地図、位置情報、カメラ、通知を使うiOSアプリの画面・端末機能を、ネイティブのAPIと同じアプリ内で組み合わせられます。
- **Firestore:** グループ、メンバー、ミッション、写真の状態をデータとして分け、クライアント間の更新をリアルタイムに反映する要件に合います。
- **Firebase Authenticationの匿名認証:** 使い捨ての待ち合わせグループという体験を、ユーザーにアカウント登録を求めず実現できます。
- **Cloud Functions:** 最初の出発に応じたミッション予約や、メンバーの到着状態を見たグループ完了判定など、端末を閉じていても共有される処理をクライアントから分離できます。
- **Google MapsとMapKitの併用:** Google Maps SDKで地図を表示し、MapKitのローカル検索で目的地を探す構成です。地図表示と検索で必要な機能を分けています。
- **Cloud Storage:** 写真データをFirestoreの状態データと分離して保存できます。Firestoreには写真URLや投稿情報を持たせる構成です。

## 主なユーザーフロー

1. グループを作成し、招待コードを共有する。
2. 参加者がプロフィールと出発予定を入力し、ロビーに集まる。
3. 出発すると地図に位置が共有され、移動中に写真ミッションが届く。
4. 写真を投稿し、メンバーの投稿にリアクションする。
5. 全員が到着するとランキングを確認し、グループのデータは期限後に削除される。

## リポジトリ構成

- `GatherQuest/GatherQuest/App`: アプリ起動、Firebase初期化、画面遷移
- `GatherQuest/GatherQuest/Models`: アプリのデータモデル
- `GatherQuest/GatherQuest/Services`: グループデータ、位置、カメラ、通知、写真保存など
- `GatherQuest/GatherQuest/Views`: SwiftUI画面と共通UI
- `functions/index.js`: ミッション予約、到着判定、定期削除処理
- `firestore.rules`、`storage.rules`: Firebaseのアクセスルール

## ローカルでの起動

このプロジェクトはXcodeとFirebaseの設定が必要です。Firebaseプロジェクト、iOSアプリのBundle ID、匿名認証、Firestore、Storage、Cloud Functionsを設定し、必要な設定ファイルとMaps SDKのAPIキーを用意してください。その後、`GatherQuest/GatherQuest.xcodeproj` をXcodeで開き、Signing & Capabilitiesで開発チームを設定して実機または対応シミュレータで起動します。Functionsの依存関係は `functions/package.json` を参照してください。
